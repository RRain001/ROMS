# ROMS Project 检查清单

用于后续正式 project 启动、运行、验证和论文写作。

## A. 研究问题

- [ ] 研究目标：水动力、污染物扩散、氚迁移、源解析、水交换、漂浮子轨迹或生态响应。
- [ ] 研究海域和边界：经纬度范围、近岸/外海边界、重点受体区域。
- [ ] 模拟时间：起止时间、spin-up、分析时段。
- [ ] 目标变量：流速、海表高度、温盐、示踪剂浓度、停留时间、贡献率等。
- [ ] 论文要回答的问题：机制解释、时空分布、源贡献、敏感性、风险评价。

## B. 数据需求

| 数据 | 必需 | 可能来源 | 检查项 |
| --- | --- | --- | --- |
| 海岸线/陆地掩膜 | 是 | GSHHS、本地 GIS | 投影、分辨率、岸线修正 |
| 地形/水深 | 是 | ETOPO, SRTM15, 本地测深 | 垂向单位、正负号、最小水深 |
| 海洋初边界 | 是 | HYCOM, CMEMS | 温盐、流速、海表高度、时间分辨率 |
| 气象强迫 | 是 | NCEP FNL, ERA5 | 风、气压、气温、湿度、辐射、降水 |
| 潮汐 | 近岸通常需要 | TPXO9/TPX | 分潮、潮位、潮流 |
| 河流/点源 | 若有陆源输入 | 监测、统计、源项清单 | 位置、流量、浓度、垂向分配 |
| 观测验证 | 是 | 潮位站、浮标、遥感、断面、监测点 | 时间对齐、空间匹配、单位 |
| 氚/污染物源项 | 若做扩散 | 排放清单、核设施报告、监管数据 | 形态、单位、排放时间序列 |

## C. 配置文件

- [ ] 记录 ROMS 源码 commit 和是否有本地 diff。
- [ ] 保存 CPP 头文件，例如 `project_name.h`。
- [ ] 保存输入文件，例如 `ocean_project.in`。
- [ ] 保存 `varinfo.yaml` 或变量元数据版本。
- [ ] 保存编译脚本和运行脚本。
- [ ] 保存环境加载脚本，包括 compiler/MPI/NetCDF/HDF5。
- [ ] 保存所有输入 NetCDF 的生成脚本和来源说明。

## D. 编译和运行

参考远端基线：

```bash
ssh lhy-desktop
cd /home/lhy/ROMS/roms_work
# 仅示例，正式运行前先确认环境和 project 配置
./build_roms.sh -j 4
mpirun -np 4 ./romsM roms_upwelling.in
```

注意：上面的运行命令不要直接用于当前远端工作目录，除非已经确认不会覆盖有用输出。正式 project 应建立独立工作目录。

## E. 输出检查

- [ ] `ncdump -h` 能读所有输出文件。
- [ ] `ocean_time` 数量和模拟时间一致。
- [ ] 维度 `xi_rho`, `eta_rho`, `s_rho`, `s_w` 与配置一致。
- [ ] 输出变量包含研究所需变量。
- [ ] 全局属性包含 `git_rev`, `CPP_options`, `script_file`, `compiler_command`。
- [ ] 历史、平均、诊断、重启文件都按预期生成。
- [ ] 检查是否有 NaN、异常极值、CFL 或 blow-up 信息。

## F. 验证和评价

建议指标：

- 平均偏差：MB
- 相关系数：r
- 一致性指数：IOA
- 均方根误差：RMSE
- 潮位相位和振幅误差
- 流速方向和大小误差
- 温盐垂向剖面偏差

`my_roms_tools` 中已有 `get_mb`, `get_r`, `get_ioa` 可参考。

## G. 论文方法写作

每个方法段至少包含：

- 模型名称、版本、源码来源。
- 研究区网格范围、分辨率、垂向层。
- 初始场和边界场来源。
- 大气、潮汐、河流/点源强迫来源。
- 示踪剂或污染物假设。
- 时间步长、模拟时长、输出频率。
- 模型验证数据和评价指标。
- 限制：数据分辨率、源项不确定性、边界条件、未考虑过程。

## H. 文件命名建议

正式 project 建议独立目录：

```text
project_name/
├── source/
├── scripts/
├── input/
├── run/
├── output/
├── postprocess/
├── figures/
└── docs/
```

不要在远端 `/home/lhy/ROMS/roms_work` 的 `UPWELLING` 基线目录中直接覆盖实验输出。
